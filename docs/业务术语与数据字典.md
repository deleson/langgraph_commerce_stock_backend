# 业务术语与数据字典

本文解释后端 API 中常见字段、枚举和状态值，方便前端展示和表单校验。

## 一、通用字段

| 字段 | 含义 | 示例 |
| ---- | ---- | ---- |
| `id` | 数据库主键 | `1` |
| `user_id` | 用户 ID，用于资源归属和隔离 | `12` |
| `created_at` | 创建时间 | `2026-06-15T10:00:00` |
| `updated_at` | 更新时间 | `2026-06-15T10:30:00` |
| `limit` | 查询条数上限 | `20` |
| `offset` | 分页偏移 | `0` |
| `total` | 列表总数 | `128` |
| `items` | 列表数据 | `[]` |
| `warnings` | 风险提示或限制说明 | `["K 线数量不足"]` |
| `errors` | 错误说明 | `["数据为空"]` |
| `disclaimer` | 免责声明 | `本结果不构成投资建议` |

## 二、市场与行情字段

| 字段 | 含义 | 可选值 / 示例 |
| ---- | ---- | ------------- |
| `market` | 市场代码 | `US`、`CN`、`HK` |
| `symbol` | 股票代码 | `AAPL`、`600519`、`0700` |
| `name` | 股票名称 | `Apple Inc.` |
| `currency` | 货币 | `USD`、`CNY`、`HKD` |
| `exchange` | 交易所 | `NASDAQ`、`SSE` |
| `provider_symbol` | Provider 使用的股票代码 | `600519.SH`、`sh.600519` |
| `list_status` | Provider 返回的上市/状态字段 | `L`、`1` 等 |
| `timeframe` | K 线周期 | `1d`、`1h`、`5m` |
| `adjust_type` | 复权类型 | `none`、`qfq`、`hfq` |
| `source` | 数据来源 | `mock`、`baostock`、`tushare` 等 |
| `latest_price` | 最新价 | `172.4` |
| `previous_close` | 前收盘价 | `170.2` |
| `open_price` | 开盘价 | `171.0` |
| `high_price` | 最高价 | `173.5` |
| `low_price` | 最低价 | `169.8` |
| `close_price` | 收盘价 | `172.4` |
| `volume` | 成交量 | `83400000` |
| `amount` | 成交额 | `123456789.00` |
| `as_of` | 行情快照时间 | ISO datetime |
| `data_hash` | 统一基础信息哈希 | sha256 字符串 |
| `raw_hash` | Provider 原始 payload 哈希 | sha256 字符串 |
| `normalized_hash` | 标准化字段哈希 | sha256 字符串 |

注意：`MarketDataSource` 的 Schema 中保留了 `akshare`、`alpha_vantage`、`polygon` 等值，但当前业务 Provider 主要实现 mock、baostock、tushare。前端不要仅凭枚举值判断某 Provider 已完整可用。

股票搜索和基础信息来源说明：

| 场景 | 当前行为 |
| ---- | -------- |
| 数据库已有可用股票基础信息 | `GET /market/stocks/search` 直接从 `market_symbols` 返回 |
| 名称 / 关键词搜索 | 只查数据库股票池，不高频调用 Tushare |
| 数据库已有但名称像占位数据 | 只有搜索词是 6 位 A 股代码时，后端才尝试 Provider 精确刷新 |
| 数据库没有匹配结果 | 只有 6 位 A 股代码会调用配置的精确查询 Provider |
| Tushare 股票池同步 | 适合通过 `POST /market-sync/symbol-pool` 或 Celery Beat 低频拉取 `stock_basic` |
| BaoStock 精确补齐 | 适合用 `query_stock_basic` 补齐单只代码，不能覆盖更高优先级的 Tushare 统一数据 |
| 搜索结果缓存 | Provider 返回的基础信息先写入 `market_symbol_sources`，再按优先级刷新 `market_symbols` |
| 前端处理 | 前端只需要展示统一返回的 `symbol`、`market`、`name`、`currency`、`exchange`、`source`，不需要直接调用 Provider |

`source` 表示数据来自哪个行情 Provider 或降级来源。它不是投资建议来源，也不代表数据一定完整可用；是否可用于技术指标、策略信号或回测，还要结合数据质量报告和 K 线数量判断。

`market_symbols` 是前端和业务查询使用的统一股票基础信息表；`market_symbol_sources` 是 Provider 来源表，用于分别保存 Tushare、BaoStock、Mock 等来源的原始基础信息、`raw_hash` 和 `normalized_hash`。哈希不替代业务键匹配，只用于判断字段是否变化，避免全量股票池同步时重复 update。

## 三、AI 分析字段

| 字段 | 含义 |
| ---- | ---- |
| `thread_id` | 分析线程 ID，用于后续追问 |
| `analysis_type` | 分析类型，当前主要是 `stock_basic` |
| `graph_route` | 主分析图路线 |
| `quality_context` | 数据质量上下文 |
| `market_snapshot` | 行情快照 |
| `indicators` | 早期基础指标快照 |
| `technical_indicators` | 完整技术指标 |
| `strategy_signal` | 策略信号 |
| `result.summary` | AI 分析摘要 |
| `result.risk_level` | AI 给出的风险等级 |
| `result.trend` | AI 给出的趋势判断 |
| `result.key_points` | 关键观点列表 |
| `result.suggestion` | 研究建议文本 |
| `result.warnings` | 风险提示 |

`graph_route` 可选值：

| 值 | 含义 | 前端展示建议 |
| ---- | ---- | ------------ |
| `normal` | 数据正常，完整分析 | 正常展示 |
| `degraded` | 数据可用但存在风险 | 展示分析，同时突出数据风险 |
| `unavailable` | 数据不可用 | 展示不可用原因，不强调 AI 结论 |
| `error` | 图执行或数据处理错误 | 展示失败提示 |
| `quota_blocked` | AI 额度不足 | 提示额度不足或稍后重试 |

## 四、技术指标字段

| 字段 | 含义 |
| ---- | ---- |
| `ma5` / `ma10` / `ma20` / `ma60` | 简单移动均线 |
| `ema12` / `ema26` | 指数移动均线 |
| `rsi6` / `rsi12` / `rsi24` | 不同周期 RSI |
| `dif` / `dea` / `histogram` | MACD 三个核心值 |
| `daily_return_std` | 日收益率标准差 |
| `annualized_volatility` | 年化波动率 |
| `momentum_5` / `momentum_10` / `momentum_20` | 不同窗口价格动量 |
| `volume_ma5` / `volume_ma20` | 成交量均线 |
| `volume_ratio` | 最新成交量 / 20 期成交量均值 |

常见标签：

| 字段 | 可选值 | 含义 |
| ---- | ------ | ---- |
| `trend` | `bullish`、`bearish`、`neutral` | 趋势偏多、偏空、中性 |
| `rsi.status` | `oversold`、`neutral`、`overbought` | 超卖、中性、超买 |
| `macd.signal` | `bullish`、`bearish`、`neutral` | MACD 动能方向 |
| `volatility.level` | `low`、`medium`、`high` | 波动率风险等级 |
| `volume_factor.status` | `shrinking`、`normal`、`expanding` | 缩量、正常、放量 |

## 五、策略信号字段

| 字段 | 含义 |
| ---- | ---- |
| `status` | 策略信号是否可用 |
| `signal` | 策略动作 |
| `strength` | 信号强弱 |
| `score` | 0 到 100 的规则分 |
| `summary` | 策略信号摘要 |
| `reasons` | 支持理由 |
| `risks` | 风险提示 |
| `rule_results` | 各规则维度评分明细 |

`signal` 可选值：

| 值 | 含义 |
| ---- | ---- |
| `buy` | 规则分偏高，研究上偏买入信号 |
| `sell` | 规则分偏低，研究上偏卖出信号 |
| `hold` | 分数接近中性，倾向持有或等待 |
| `observe` | 数据或信号不够强，建议观察 |

注意：`buy` / `sell` 不是投资建议，也不是交易指令。

## 八、日报模式字段

| 字段 | 含义 |
| ---- | ---- |
| `daily_report_enabled` | 当前用户是否开启自动日报模式，保存在 `user_preferences` 中 |
| `scheduler_enabled` | 后端部署级 Celery Beat 日报调度是否开启，只由服务端配置控制 |
| `effective_status` | 当前日报模式的综合状态 |
| `timezone` | 当前用户时区，用于展示和后续日报时间解释 |
| `message` | 后端返回给前端展示或调试的状态说明 |

`effective_status` 可选值：

| 值 | 含义 |
| ---- | ---- |
| `disabled` | 用户未开启日报模式 |
| `enabled` | 用户已开启日报模式，且服务端已启用定时日报调度 |
| `enabled_but_scheduler_off` | 用户已开启日报模式，但服务端未启用定时日报调度 |

注意：前端按钮只能控制当前用户的 `daily_report_enabled`，不能控制 `scheduler_enabled`。即使日报模式关闭，用户仍然可以手动调用 `POST /daily-reports/generate` 生成日报。

## 十、认证与会话字段

| 字段 | 含义 |
| ---- | ---- |
| `session_id` | 服务端登录会话 ID，access token 会绑定该 ID，后端鉴权时用它确认当前会话是否仍有效 |
| `device_platform` | 登录设备平台，可选值为 `android`、`ios`、`web`、`unknown` |
| `device_category` | 登录设备类别，可选值为 `mobile`、`web`、`unknown`；`android` 和 `ios` 会归类为 `mobile` |
| `device_fingerprint` | 前端生成并持久保存的稳定设备指纹，后端只保存 hash，用于辅助审计和排查 |
| `device_fingerprint_hash` | 后端保存的设备指纹哈希，不直接保存客户端原始指纹 |
| `device_name` | 设备名称，例如手机型号、浏览器名称，用于设备列表和排查问题 |
| `app_version` | 登录时的 App 版本号，用于兼容性排查 |
| `access_token_jti` | access token 的唯一编号，便于服务端拉黑旧 token |
| `is_revoked` | 当前 session 是否已被撤销 |
| `revoked_at` | session 被撤销的时间 |
| `revoked_reason` | session 撤销原因，例如 `logout`、`refresh_rotated`、`replaced_by_same_category_login` |
| `replaced_by_session_id` | 当前 session 被新同类设备登录替换时，对应的新 session ID |
| `replaced_sessions_count` | 登录响应字段，表示本次登录替换了多少个旧同类设备 session |

`revoked_reason` 常见取值：

| 值 | 含义 | 前端建议 |
| ---- | ---- | ---- |
| `logout` | 用户主动退出登录 | 清空本地 token，回到登录页 |
| `refresh_rotated` | refresh token 刷新后旧 session 被轮换撤销 | 正常使用新 token，不提示异常 |
| `replaced_by_same_category_login` | 同账号在另一台同类设备登录，旧 session 被替换 | 弹窗提示后清空 token 并跳转登录页 |
| `admin_revoked` | 后台或管理动作撤销 | 提示登录状态失效并重新登录 |
| `expired` | session 已过期 | 重新登录 |

同类设备单会话规则：

```text
android / ios -> mobile；
web -> web；
unknown -> unknown。

默认情况下，同一账号同一时间只能保留一个 mobile session 和一个 web session。
unknown 类别为兼容旧客户端，默认不参与互踢，可通过后端配置开启。
```
